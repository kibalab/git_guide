고양이도 이해하는 Git 사용법

이 문서는 아트 직군 입문자를 위해 만든 Git 설명서입니다. 어려운 말은 줄이고, 꼭 필요한 용어만 단계적으로 소개합니다.

이 문서는 Git의 개념과 원리를 이해하는것이 목적이며, 특정 Git 클라이언트나 명령어를 직접 사용하는 방법은 다루지 않습니다.

각 조직에서 쓰는 Git 환경 안에서 규칙을 더 쉽게 이해하고, 매일 하고 있는 커밋, 푸시, 풀, 머지 같은 행동이 실제로 무엇을 의미하는지 파악해 협업을 더 수월하게 만드는 데 초점을 맞춥니다.

각 장은 독립 페이지로 되어 있고, 이해를 돕기위해 상호작용이 가능한 Git 그래프 렌더러로 시각자료를 제공합니다.

모두가 Git을 편하게 다룰수 있도록, 이 안내서가 작은 도움이 되길 바랍니다.

목차

앞에서 정의한 개념을 뒤에서 자연스럽게 이어서 쓰도록 구성했습니다.

  1. 1장 로컬/리모트 레포지토리 정의 Git과 GitHub를 구분하고 로컬과 리모트 기록 저장소의 관계를 이해합니다.
  2. 2장 히스토리, 추적단위(파일/라인) 정의 사람이 읽을 수 있는 파일을 기준으로 히스토리와 줄 단위 비교가 어떻게 보이는지 익힙니다.
  3. 3장 HEAD, 브렌치 정의 HEAD, 브렌치, Checkout의 역할과 브렌치 이름을 정하는 기준을 정리합니다.
  4. 4장 커밋, Push, Fetch 정의 커밋 단위와 Push, Fetch가 기록 저장소 사이에서 무엇을 바꾸는지 시각적으로 봅니다.
  5. 5장 Merge, Pull, 컨플릭트 Merge와 Pull의 흐름, 그리고 컨플릭트가 왜 생기고 어떻게 읽어야 하는지 이해합니다.
  6. 6장 Pull Request (PR) 검토와 머지 요청 흐름을 보고, 작업을 마무리할 때 어떤 순서가 좋은지 정리합니다.

번외

실무에서 자주 부딪히는 운영 방식은 따로 묶어서 바로 찾아볼 수 있게 정리했습니다.

  1. 번외 1 커밋메시지 작성 전략 나중에 다시 읽어도 이해되는 커밋 메시지를 남기는 기준을 정리합니다.
  2. 번외 2 브렌치 운용 전략 브렌치를 어떤 작업 단위로 나누고 언제 정리하는지 대표적인 방식을 소개합니다.
  3. 번외 3 컨플릭트 해결 전략 충돌이 났을 때 무엇을 남기고 무엇을 버릴지 판단하는 순서를 정리합니다.
  4. 번외 4 이런 이상한 시스템은 누가 만들었나요 Git을 만든 리누스 토르발즈와 Git이 이런 성격을 가지게 된 배경을 짧게 소개합니다.

猫でもわかるGitの使い方

この文書は、アート職の入門者に向けて作った Git ガイドです。 難しい表現は省略し、本当に必要な用語だけを順番に紹介します。

目的は Git の概念と仕組みを理解することです。 通常の表示では、特定の Git クライアントやコマンドの操作手順そのものは扱いません。 上部の「コマンド説明を表示」をオンにすると、各機能に対応するコマンド例も確認できます。

それぞれの組織で使っている Git 環境のルールを理解しやすくし、 毎日行っている Commit、Push、Pull、Merge が実際には何をしているのかをつかんで、 共同作業を少しでも進めやすくすることに焦点を当てています。

各章は独立したページになっていて、理解を助けるために 操作できる Git グラフの図も用意しています。

Gitを少しでも上手に扱えるようにする小さな助けになればと思います。

目次

前で定義した概念を、後ろの章でも自然に使えるように順番を組んでいます。

  1. 第1章 ローカル/リモートリポジトリの定義 Git と GitHub の違いを分けて考え、ローカルとリモートの記録保存先の関係を理解します。
  2. 第2章 履歴と追跡単位（ファイル/行） 人が読めるファイルを基準に、履歴や行単位の比較がどう見えるのかをつかみます。
  3. 第3章 HEAD とブランチ HEAD、ブランチ、Checkout の役割と、ブランチ名の付け方を整理します。
  4. 第4章 Commit、Push、Fetch Commit の単位と、Push、Fetch が保存先どうしで何を変えるのかを図で確認します。
  5. 第5章 Merge、Pull、コンフリクト Merge と Pull の流れ、そしてコンフリクトがなぜ起きてどう読めばよいのかを理解します。
  6. 第6章 Pull Request (PR) レビューとマージ依頼の流れを見ながら、作業を締める順番を整理します。

補足

実務でよくぶつかる運用テーマは、別枠でまとめてすぐ見返せるようにしました。

  1. 補足 1 コミットメッセージの書き方 あとから読み返しても意味が通るコミットメッセージの基準を整理します。
  2. 補足 2 ブランチ運用戦略 ブランチをどんな作業単位で分け、いつ片づけるのか代表的なやり方を紹介します。
  3. 補足 3 コンフリクト解決戦略 衝突が起きたとき、何を残して何を捨てるかを判断する順番を整理します。
  4. 補足 4 こんな変わった仕組みを作ったのは誰？ Git を作ったリーナス・トーバルズと、Git がこういう性格になった背景を短く紹介します。

おすすめの順番: まず第1章から第6章まで読み、そのあと必要に応じて補足を確認してください。

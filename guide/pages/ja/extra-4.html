補足 4. こんな変わった仕組みを作ったのは誰？

Git を作った人は リーナス・トーバルズ（Linus Torvalds）です。 聞き慣れない用語や独特な感覚のせいで「いったい誰がこんな仕組みを作ったんだ」と思うかもしれませんが、 その背景を知ると Git の性格も少し理解しやすくなります。

リーナス・トーバルズとは誰か

リーナス・トーバルズはフィンランド出身のソフトウェア開発者で、 Linux カーネルを作った人物として最もよく知られています。 とても大きな規模の開発を長く扱ってきたので、 道具を作るときも「大勢が同時に作業しても耐えられるか」をとても重視するタイプです。

GitHub のようなサービスが先にあったのではなく、 まず Git が作られ、そのあとで Git を使いやすくするためのサービスやクライアントが増えていきました。 つまり、リーナスが作ったのはウェブサイトではなく、記録を保存して統合する仕組みそのものに近いものです。

なぜ Git を作ったのか

2005 年ごろ、Linux カーネルのような非常に大きなプロジェクトを複数人で同時に進めるために、 高速で信頼できる記録管理ツールが必要になりました。 それまで使っていた道具を継続しにくくなったため、 リーナスは短い期間で自分の手で新しい道具を作り始めました。

そのため Git は最初から「入門者にやさしく教える道具」よりも、 大規模な共同作業で記録を安全に残し、素早く統合する道具として設計されました。 今わたしたちが感じる独特な使い心地も、かなりここから来ています。

だから Git はなぜこういう形なのか

  • ローカル記録保存先を強く見る理由: ネットワークがなくても作業記録とブランチを十分扱える必要があったからです。
  • ブランチと Merge が重要な理由: 複数人が同時に分かれて作業し、あとでまた統合することが日常だったからです。
  • 用語や操作感がやや無骨な理由: 見た目のきれいさより、速度、安定性、記録の信頼性が先だったからです。
  • 履歴を厳密に扱う理由: 「誰が何をいつ変えたか」を信頼できないと、大きなプロジェクトは保てないからです。

一言でまとめると

Git は最初から誰にでもやさしい学習ツールとして生まれたのではなく、 大きなプロジェクトの共同作業に耐えるためのエンジニアリングツールとして生まれました。

アート職の立場で覚えておくとよい点

Git が最初はよくわからず、少し変に感じられるのは自然なことです。 この道具は文書編集ソフトのようにやわらかく親切に設計されたのではなく、 複雑な共同作業を壊さず守ることを優先した仕組みだからです。

だから Git の内部原理を全部深く掘る必要まではありませんが、 なぜローカルとリモートが分かれていて、なぜブランチを分け、なぜ Merge やコンフリクトを重く見るのかは理解しておく価値があります。 そこだけでも分かれば、「いま自分が何をしているのか」がかなりはっきりします。
